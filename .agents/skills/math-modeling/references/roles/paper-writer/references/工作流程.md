# 论文手工作流程

## 一、锁定官方规则

生成前确认目标竞赛、届次、语言和官方规则来源。优先使用用户提供或从官方网站取得的当届官方 Word 模板、摘要页、编号页和格式说明。把规则来源与届次记录在内部检查中，不把往届经验写成固定规则。

## 二、检查输入

必须具备：

- 题目及附件
- `题目分析报告.md`
- `术语表格.md`
- 可运行代码
- 实际运行结果表格
- 原始数据图、模型运行过程图和最终结果图
- 已核验的文献元数据

关键输入缺失时回退到对应角色补齐，不能推测数值、伪造图表或编造引用。

若用户提供或授权优秀论文案例，先锁定未参考案例的独立版本，再建立“借鉴点—独立证据—
采用/拒绝理由”内部清单。只学习章节节奏、摘要信息密度、图表组织、公式解释和结果呈现；
案例的公式、数值和结论必须另行核验，案例身份或奖项不构成正确性证据。
具体检索、七遍拆解、案例学习记录表、详细章节格式和验收清单必须完整执行
`优秀论文学习与写作格式.md`。

## 三、内部论证映射

写作前在内存或临时工作区建立主张—证据映射：每个结论对应公式、表格、图、代码输出或文献。映射只用于检查，不作为额外交付物。

同时记录两类篇幅约束：一类是当届官方页数、摘要和文件限制，必须满足；另一类是用户明确要求或根据本题论证需求预先声明的质量区间。没有依据时不设固定最低字数、恰好页数、摘要填充率或公式/图/表数量。正文页数、PDF 总页数、摘要页和附录页必须按官方定义分别统计，不能互相替代，也不能根据字符数猜测。不得靠重复、空泛文字、放大图表、强制分页或制造空白达成质量目标。

不要把优秀案例中代码页占比约20%等观察值转化为硬约束。代码附录的首要要求是全部、完整、可运行并与支撑材料一致；可在不删减必要源码的前提下改善字号、行距、折行和空行，但不得为了压低占比而省略程序。

规划图形时同时考虑“结果证据图”和“方法解释图”。前者从真实运行数据生成；后者可用 Python、矢量绘图或流程图工具生成算法流程、模块关系、几何构造与验证闭环。每幅图都必须在正文被引用并承担具体信息功能，解释图不得伪造数值、误导比例或替代必要的结果证据。

## 四、构建候选 DOCX

1. 从当届官方参考模板创建文档；模板正文示例必须清除，但保留样式、分节、页眉页脚和页面设置。
2. 使用 `../../../../tools/docx/scripts/paper_format.py` 添加标题、段落、公式、表和图片。
3. LaTeX 只作为公式输入，转换成 Word 原生 OMML；不支持的命令必须报错。
4. 表格使用可编辑 Word 表格；图使用编程手实际生成的文件。
5. 每幅图和每个表均设置连续编号与题注，并在正文中至少引用一次；文献编号、正文引用和 DOI 双向核对。
6. 摘要按问题1至问题n独立成段或成行，并将各题核心方法和最终结果设为原生粗体；正文前部设置问题背景和逐题重述。
7. 输出文件名必须为 `论文候选稿.docx`。`完整论文.docx` 是发布结果，不能由构建脚本直接写出。

## 五、验证

```powershell
python ../../../../tools/docx/scripts/self_check.py
python ../../../../tools/docx/scripts/office/validate.py "<PROJECT_ROOT>/论文候选稿.docx"
```

使用发布清单指定的渲染器渲染候选稿，并运行 `paper_release_gate.py`。门禁按清单中的分页结构测量摘要、正文和附录，核对动态摘要必答项、官方规则与模板、候选稿与渲染 PDF、结果注册表、红队审计、图表编号引用和参考文献。官方硬约束、证据锁定和结构错误必须阻断；质量检查是否阻断由清单预先声明，代理不能事后撰写覆盖理由。只有门禁返回 `status=pass` 时才生成 `完整论文.docx`。

## 六、交付

交付由门禁发布的 `PROJECT_ROOT/完整论文.docx`；当届官方提交格式包含 PDF 时，同时交付同一门禁发布的 `PROJECT_ROOT/完整论文.pdf`。候选稿、发布清单、内部映射和检查日志是内部文件，不作为交付物。
