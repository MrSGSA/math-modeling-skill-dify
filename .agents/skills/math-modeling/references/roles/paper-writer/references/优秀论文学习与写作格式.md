# 优秀论文学习工作流与详细写作格式

本文件规定如何从优秀案例中学习可迁移的写作方法。案例用于发现表达结构、验证方式和
可能遗漏，不是当前题的答案、参数来源或正确性证据。

## 目录

1. 依据与优先级
2. 何时开始学习案例
3. 案例选择与知识库检索
4. 七遍拆解法
5. 案例学习记录表
6. 详细写作格式
7. 从案例到当前论文的采用规则
8. 发布前验收

## 一、依据与优先级

执行顺序始终是：

1. 当届官方规则和模板；
2. 用户追加硬限制；
3. 当前题题面、附件、独立代码和真实结果；
4. 知识库中的论文写作规范、错题与实践复盘；
5. 同竞赛优秀案例；
6. 其他竞赛或其他题型案例。

低层级材料与高层级冲突时，舍弃低层级写法。不得把优秀案例常见做法包装成官方要求。

知识库依据：

- 数学建模-竞赛规则库，《全国大学生数学建模竞赛论文格式规范（2026年修订稿）》：
  摘要原则上不超过一页，正文与附录分开计量，附录包含完整可运行程序，引用必须标注。
- 数学建模-实践复盘库，`2024A复盘1.md`：数值结果图回答“算出了什么”，算法、几何或
  机制解释图回答“为什么这样算”；验证、稳定性和适用边界应形成真实篇幅。
- 数学建模-实践复盘库，`2023A实践1.md`：案例只提供结构启发，当前题的判据、参数、
  程序和数值必须重新推导与运行。
- 数学建模-错题本，`2024A错题1.md`：只有数值结果图、缺少解释图属于已验证写作错误。
- 数学建模-错题本，`2023A错题1.md`、`2025A错题1.md`：旧结果混入、不同表格抄成
  矛盾数值是高频错误，应使用单一结果源和跨表一致性检查。
- 数学建模-优秀案例库，`2025-A196.md`：符号下标过密会破坏可读性，算法过程过长会
  造成阅读疲劳。
- 数学建模-优秀案例库，`2022-A022.md`、`2024-A163.md`：模型评价应落到原创结构、
  精度、简化依据和可推广性，不能只写通用套话。

知识库命中只作为本工作流依据；使用某个具体案例时，另行记录知识库名和来源文档。

## 二、何时开始学习案例

只在以下材料完成后开始：

- 题面与附件已读取；
- 独立题目分析和术语表已形成；
- 主模型与代码已有可运行版本；
- 关键结果已写入结果注册表；
- 独立版本已保存并记录 SHA-256。

若案例在独立建模前已被读取，必须把案例带来的模型、参数和数值列为潜在污染项，逐项用
题面、文献和独立运行重新验证。

## 三、案例选择与知识库检索

### 3.1 选择顺序

至少从不同来源交叉选择，优先顺序为：

1. 同一竞赛、同一届次、同一题；
2. 同类机理或同类任务的优秀论文；
3. 论文写作库中的规范或经验；
4. 实践复盘库和错题本中的已验证经验；
5. 多模态库中与摘要页、流程图、结果表或验证图直接相关的原图。

单篇案例不能单独决定论文结构。若只有一篇，标记“单案例观察”，不得升级为通用规律。

### 3.2 必做检索

按当前题替换方括号内容，至少检索：

1. `[竞赛年份题号] 优秀案例 摘要 方法 结果 验证`
2. `[题型/领域] 优秀论文 模型建立 算法流程 结果分析`
3. `[核心模型] 稳健性 灵敏度 误差分析 模型检验`
4. `数学建模论文 常见错误 摘要 图表 公式 数值一致性`
5. `优秀论文 流程图 结果表 验证图 多模态`

主体依据来自文本库；仅当页面布局、图表或原图对当前任务有直接帮助时查询多模态库。
记录知识库名、来源文档、相关段落、可迁移命题和相关度；低相关命中不得写成事实。

## 四、七遍拆解法

不从头模仿措辞，按七个独立维度拆解。

### 第一遍：一页结构地图

记录：

- 摘要、正文、参考文献和附录的实际起止页；
- 一级、二级、三级标题；
- 每个子问题占用的章节；
- 图、表、公式和验证首次出现的位置；
- 哪些章节承担主要结论，哪些内容可以删掉而不影响证据链。

输出“章节—任务—证据”地图，不复制正文。

### 第二遍：摘要逆向提纲

对每个子问题提取：

- 任务对象；
- 核心方法；
- 关键改进；
- 最终定量结果；
- 验证证据；
- 适用边界。

检查摘要中的每个结果能否在正文表格或结果注册表中定位。优秀案例若只有“建立模型并
求解”而没有数值，不采纳其摘要写法。

### 第三遍：子问题证据单元

把每个子问题拆为：

`任务 → 数据/条件 → 假设 → 变量 → 模型 → 算法 → 结果 → 验证 → 小结`

判断案例是否缺少其中某一环。当前论文只学习完整证据单元，不机械照搬标题名称。

### 第四遍：公式与符号

记录：

- 关键公式出现前是否交代物理/统计意义；
- 公式后是否解释符号、单位和允许域；
- 推导是否保留关键中间步；
- 公式是否在后续算法或验证中真正使用；
- 是否出现符号重复、下标过密或同义符号。

只吸收“定义清楚—推导必要—程序使用—结果验证”的公式组织方式。

### 第五遍：图表叙事

给每幅图表标注职责：

- 数据诊断图；
- 机制/几何解释图；
- 算法流程图；
- 主结果图；
- 模型比较图；
- 稳健性/灵敏度图；
- 误差或不确定度图；
- 主结果表；
- 参数/符号表；
- 验证表。

检查是否做到“正文先提出问题—图表给证据—正文解释结论”。孤立图表、装饰图和重复
展示同一数值的图表不学习。

### 第六遍：验证与模型评价

提取案例实际使用的验证：

- 解析极限或手算基准；
- 合成数据恢复；
- 独立方法交叉验证；
- 训练/验证或留出检验；
- 参数扰动与边界放宽；
- 网格、随机种子或搜索预算收敛；
- 跨角度、跨附件、跨情景一致性；
- 残差结构与极端反例；
- 单位、守恒、单调性和物理可行性。

模型优点必须对应已展示证据；局限必须说明影响范围、触发条件和改进办法。

### 第七遍：反向挑错

主动检查案例是否存在：

- 摘要、正文、表格、图和代码数值不一致；
- 结论有效位数超过误差证据；
- “全局最优”“显著提高”“证明正确”等措辞过强；
- 参数可计算但不可辨识；
- 异常值、筛选区间或搜索范围未披露；
- 同一数据拆成大量相关样本后虚假缩小误差；
- 公式和程序实现不一致；
- 引用缺失或大篇幅近似照抄题面/他文。

发现错误时记录为防错项，不把错误带入当前论文。

## 五、案例学习记录表

每篇案例至少建立一行记录：

| 字段 | 内容 |
|---|---|
| 案例来源 | 知识库名、来源文档、竞赛、年份、奖项或作者身份 |
| 可学习对象 | 摘要、章节、公式、图表、验证或评价 |
| 原案例做法 | 只概括结构，不长段复制 |
| 可检验命题 | 可由当前题题面、代码或结果验证的陈述 |
| 当前题独立证据 | 文件、函数、图表、结果键或文献 |
| 决定 | 采用、改写后采用、拒绝 |
| 理由 | 与当前题的相容性和风险 |
| 污染风险 | 是否包含同题数值、参数或结论 |
| 写入位置 | 当前论文的具体章节 |
| 验收方式 | DOCX、PDF、结果注册表或红队检查 |

没有“当前题独立证据”的案例做法不得进入最终论文。

## 六、详细写作格式

章节名称首先服从官方模板。官方未固定时，使用下列结构。

### 6.1 标题

- 准确包含研究对象和核心方法或任务；
- 不使用“关于某问题的研究”等空泛标题；
- 不写奖项、学校、作者、模型厂商或身份信息；
- 标题中出现的方法必须在正文成为主模型。

### 6.2 摘要页

建议顺序：

1. 一至两句说明对象、数据和总目标；
2. **问题1：** 独立一段，写 **核心方法**、关键处理和 **最终结果**；
3. **问题2：** 独立一段，写 **核心方法**、关键处理和 **最终结果**；
4. 依次写至 **问题n**；
5. 一段汇总最有区分力的验证、稳健性证据和适用边界；
6. 关键词 3～6 个，以研究对象、核心模型和关键算法为主。

每个问题段遵循：

`问题标签 + 任务 + 粗体方法 + 必要改进 + 粗体定量结果 + 一项验证`

示例骨架：

> **问题一：** 针对……，建立 **[模型名称]**，通过……求解，得到
> **[结果、单位与不确定度]**；经[验证方法]，误差/稳定性为……。

摘要禁止：

- 只有背景和方法名，没有定量结果；
- 罗列软件、数据行数、随机种子或长参数表；
- 使用正文未出现的结果；
- 只加粗问题标签，不加粗方法与结果；
- 为填满一页重复结论或扩大字号、行距。

### 6.3 问题背景

按照题面顺序忠实说明：

- 现实对象和应用场景；
- 需要解决的核心矛盾；
- 题目给出的数据或实验背景；
- 建模结果的实际用途。

背景一般不放模型、结果和作者假设，不自行补写题面没有的行业事实。使用外部背景资料时
必须引用。

### 6.4 问题重述

按问题1至问题n逐项写：

- 已知输入；
- 给定条件；
- 要求建立或求解的对象；
- 输出形式；
- 与前一问题的继承关系。

可以贴近题面重写，但不得遗漏条件、改变任务，也不能把后续假设写成题目条件。

### 6.5 问题分析

先写全题结构，再逐题分析：

- 为什么困难；
- 哪些量可观测、哪些量待估；
- 各子问题之间共享什么内核；
- 候选模型有哪些；
- 为什么选择当前模型，何时需要升级；
- 预期使用什么证据验证。

问题分析不提前堆公式，不把最终结果倒写成选择模型的理由。

### 6.6 模型假设

每条假设包含：

`假设内容 + 题面/数据/文献依据 + 影响范围 + 可检验或推翻条件`

删除不参与公式、算法或解释的空泛假设。对可能改变最终结论的强假设，必须做情景或
敏感性分析。

### 6.7 符号说明

- 优先使用一张可编辑三线表；
- 列出符号、含义、单位、类型或取值域；
- 只收入正文多次使用的核心符号；
- 同一物理量全篇只用一个符号；
- 避免多层下标；无法避免时按对象—时间—情景固定次序；
- 已知量、决策变量、状态变量和估计参数应可区分。

### 6.8 每个子问题的固定证据结构

每个问题按需要采用以下小节：

1. 数据处理或条件整理；
2. 模型准备与变量定义；
3. 模型建立；
4. 求解算法；
5. 计算结果；
6. 模型检验或稳健性分析；
7. 本问小结。

每个问题至少形成一个闭环：

`题面任务 → 数学定义 → 可运行算法 → 定量结果 → 独立验证 → 明确回答`

若某问题只需理论推导，可以用解析极限、量纲、边界情况或与后续数据的一致性代替数值
实验，但不能省略验证。

### 6.9 模型建立

按以下顺序写：

1. 模型目的和输出；
2. 变量、参数及单位；
3. 机制、统计或优化依据；
4. 核心关系的逐步推导；
5. 目标函数；
6. 约束条件；
7. 初始/边界条件；
8. 参数来源、有效域和可辨识性；
9. 简化模型与完整模型的关系。

不要先给一大组公式再解释。核心公式前交代“为何需要”，公式后解释“每项表示什么、
怎样进入算法、怎样验证”。

### 6.10 求解算法

正文说明：

- 输入和输出；
- 初始化或粗估；
- 主循环/搜索/拟合步骤；
- 停止条件；
- 参数范围和预算；
- 异常、无解或多解处理；
- 时间复杂度或主要计算开销；
- 随机算法的种子与重复策略。

正文保留能让评委复核的逻辑，不逐行解释代码。完整代码放附录或支撑材料。

### 6.11 结果呈现

主结果先表后图或先图后表均可，但职责必须分开：

- 主结果表：精确列出方案、关键决策/参数、最终值、单位、不确定度或误差；
- 结果图：展示趋势、空间结构、拟合、残差或模型差异；
- 正文：解释最重要的两至三条发现，以及它们怎样回答题目。

所有重复数值从结果注册表自动回填。结果保留位数由不确定度或误差决定，不由程序输出
小数位数决定。

### 6.12 图的格式与职责

- 图题置于图下，连续编号；
- 坐标轴写名称和单位，图例与正文术语一致；
- 正文必须在图前引用，图后解释；
- 数值图来自真实代码结果；
- 流程、几何、机制和验证闭环图可为解释图，但不得伪造数值比例；
- 一图只承担一个主论点，多子图需用 (a)(b) 标记并分别解释；
- 避免三维装饰、彩虹色、过密标记和不可辨认小字；
- 黑白打印时仍应可区分。

优先配置：

- 原始数据诊断图；
- 核心模型/算法解释图；
- 主结果图；
- 模型对比或残差图；
- 稳健性、敏感性或误差图。

### 6.13 表的格式与职责

- 表题置于表上或按官方模板，全文一致；
- 使用可编辑三线表；
- 单位写在列名，不在每个单元格重复；
- 小数位按精度统一，对齐小数点；
- 缺失、不可用和未计算使用不同标记并在表下注释；
- 表格前说明比较目的，表格后解释结论；
- 宽表优先拆分或移入附录，不以极小字号硬塞。

### 6.14 公式格式

- 公式使用 Word 原生 OMML，居中并连续编号；
- 正文用“式（x）”引用；
- 新符号在首次出现处解释并给单位；
- 向量、矩阵、随机变量和集合的字体约定全篇一致；
- 长推导保留关键变形，机械代数放附录；
- 公式必须与代码实现逐项对应；
- 无法进入算法、结果或解释的公式应删除。

### 6.15 验证、灵敏度和误差

优先验证最可能改变结论的环节，不机械罗列：

- 数据质量与泄漏；
- 单位和量纲；
- 解析极限、守恒和单调性；
- 合成数据恢复；
- 训练外、时间外、空间外或情景外验证；
- 不同方法交叉验证；
- 参数、网格、随机种子和搜索预算；
- 残差结构、异常点和极端反例；
- 约束重拟合与参数可辨识性；
- 不确定度传播与有效位数。

每项验证写成：

`验证对象 + 方法 + 数值结果 + 通过标准 + 对结论的影响`

### 6.16 模型评价与推广

模型优点按证据写，例如：

- 哪个机制被保留；
- 哪个验证通过；
- 相比嵌套基线改善多少；
- 哪些参数或结构可推广。

模型局限写：

- 具体缺失或假设；
- 影响哪个结果；
- 在什么条件下触发；
- 当前有什么缓解；
- 需要什么新数据或方法改进。

重大缺陷不能留到评价部分后继续声称结果可靠，应返回前面修复或降级结论。

### 6.17 结论

按问题1至问题n逐项回答：

- 最终模型或判据；
- 最终结果与单位；
- 不确定度、误差或可行性状态；
- 关键验证；
- 适用条件。

结论不得引入正文未出现的新数据和新模型。

### 6.18 参考文献

- 只列正文实际引用的文献；
- 正文引用与文末条目双向对应；
- 参数、公式、数据和软件资料分别在使用处引用；
- 优先原始论文、标准、官方文档和教材；
- 核验作者、题名、年份、卷期页和 DOI；
- 优秀案例若影响了实质方法或表达，应按竞赛规则决定是否引用，不得大篇幅照抄。

### 6.19 附录和支撑材料

按官方规则包含：

- 支撑材料文件列表；
- 全部完整、可运行源代码；
- 大型中间表或补充推导；
- 复现环境和运行入口；
- 结果文件与正文主张的对应关系。

正文必须自洽，不能把关键模型、主要结果或必要验证全部推入附录。

## 七、从案例到当前论文的采用规则

### 可以直接学习

- 标题层级和阅读节奏；
- 摘要逐题回答结构；
- 图表职责与前后解释方式；
- 公式—算法—结果衔接；
- 验证种类和模型评价框架。

### 必须改写并验证

- 模型名称和数学表达；
- 参数、阈值、搜索范围；
- 数据清洗和异常剔除；
- 算法流程和停止条件；
- 结果、误差、结论和适用边界。

### 禁止复制

- 案例最终数值作为当前题目标；
- 未核验的参数和公式；
- 案例内部错误或过强措辞；
- 大段原文、专有句式或整图整表；
- 为接近获奖答案而反向调整当前结果。

## 八、发布前验收

### 摘要

- [ ] 问题1至问题n分别成段或成行；
- [ ] 每题方法和最终结果均为原生粗体；
- [ ] 每题有定量回答；
- [ ] 至少给出关键验证与适用边界；
- [ ] 摘要、正文、表格和结果注册表一致；
- [ ] 未靠空话或版式膨胀填页。

### 正文

- [ ] 问题背景和逐题重述与题面一致；
- [ ] 每个子问题形成模型—算法—结果—验证闭环；
- [ ] 公式均被解释和使用；
- [ ] 结果图与解释图共同构成证据；
- [ ] 每幅图表均被正文引用和解释；
- [ ] 模型优缺点有证据和影响范围；
- [ ] 参考文献双向对应；
- [ ] 代码、结果表和论文来自同一运行版本。

### 案例学习

- [ ] 至少记录案例来源和知识库文档；
- [ ] 已建立案例学习记录表；
- [ ] 同题案例数值未进入调参目标；
- [ ] 所有采用项均有当前题独立证据；
- [ ] 案例内部矛盾已记录并独立复算；
- [ ] 优秀案例只提升表达和验证，没有替代独立建模。
