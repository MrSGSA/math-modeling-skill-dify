# 论文手

## 路径

- `ROLE_ROOT`：本文件所在目录。
- `SKILL_ROOT`：`ROLE_ROOT/../../..`，只读。
- `PROJECT_ROOT`：用户项目目录，论文只写这里。

## 唯一交付物

`PROJECT_ROOT/完整论文.docx`。论文仅供参考。

## 官方规则优先级

1. 用户提供的当届官方模板和规则。
2. 从目标竞赛官方网站取得的当届模板和规则。
3. `references/论文模板.docx` 与 `../../../tools/docx/scripts/paper_format.py` 只作为无官方模板时的构建基线，不得声称替代当届官方文件。

在生成前明确竞赛名称、届次、语言和官方规则来源。官方结构、页型、页边距、摘要页、页数、编号和提交格式均以当届规则为准。

同时明确篇幅质量目标。CUMCM未取得当届更具体要求时，摘要以渲染后内容充实、接近写满且不溢出一页为目标，不设固定字数；正文以渲染后恰好30页为优选质量目标。二者均是可调整的写作目标，不是官方最低要求。以2026年官方规范为例，正文不超过30页，附录页数不限；电子版论文没有总页数上限，单文件大小不超过20MB。完整可运行源码和支撑材料文件列表须放入论文附录，源码还须包含在单独提交的支撑材料中。不得另设“代码附录占全文不超过20%”等无官方依据的比例限制。默认将附录与正文统一为 A4 竖版单栏并使用正常可读字号；不得为压缩页数擅自改成横版、双栏或极小字号，除非官方模板或用户明确要求。一级标题默认承接上文连续排版，不得逐章强制分页制造页尾空白；只在摘要、正文、附录等结构边界或确有排版需要时分页。

图形既包括真实代码结果图，也包括帮助读者理解模型的算法流程图、模型结构图、几何解释图、变量关系图和验证逻辑图。解释类图形可用 Python、矢量工具或流程图工具生成，不要求全部由主求解语言绘制；但必须与最终模型、符号、算法和代码一致，并在正文承担明确的解释作用。数值图只能使用真实运行结果，禁止用示意图冒充结果图。

## 执行顺序

1. 读取题目、`题目分析报告.md`、`术语表格.md`、全部真实运行表格、图和代码。
2. 读取通过评审门的 `results/red_team_audit.json` 与 `results/result_registry.json`；关键审计未通过时禁止开始定稿。
3. 用 Claim-Evidence 映射核对每个主张；缺证据时回退到评审手指定的建模手或编程手，禁止编造。所有重复数值从结果注册表写入，不在论文脚本中手工复制。
4. 若发现会使核心结论失效的重大缺陷，先回退修复或替换模型，不把重大缺陷留到“模型评价”中自我否定，也不得隐瞒后继续声称结论可靠。
5. 按审计文件标注的证据强度使用“可行方案、当前预算下较优、离散层全局最优、全局最优”等措辞，不得升级结论。
6. 按官方结构写完整正文，引用由双引擎搜索结果和原始出版页面核验。
7. 使用 `../../../tools/docx/SKILL.md` 和 `paper_format.py` 从官方参考模板构建 DOCX；公式必须为 Word 原生 OMML，表格必须可编辑。
8. 运行 DOCX 结构、篇幅、公式、图表、编号引用和参考文献对应检查，再进行渲染页数抽检；所有预警必须修正，或根据当届官方规则记录明确的覆盖理由后才能交付。
